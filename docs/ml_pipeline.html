ML Pipeline

Orchestrating end-to-end ML workflows on Azure

What Is an ML Pipeline?

A Machine Learning (ML) Pipeline is a series of automated and reproducible steps that transform raw data into trained, evaluated, monitored, and registered machine learning models.

Instead of executing individual scripts manually, a pipeline connects all stages of the machine learning workflow together, allowing the entire process to be triggered, tracked, and repeated consistently.

In this project, the ML pipeline uses the NYC Taxi dataset stored in Azure and performs:

  • Data preprocessing
  • Supervised learning
  • Unsupervised learning
  • Model registration
  • Monitoring and artifact generation

This approach follows MLOps best practices by ensuring that model training and evaluation can be executed repeatedly in a controlled and automated manner.

Pipeline Architecture

This project uses two layers of automation:

  1. GitHub Actions CI/CD Pipeline
  2. Azure Machine Learning Pipeline

Together, these components automate the workflow from source code execution in GitHub to model training and tracking in Azure Machine Learning.

GitHub Actions CI/CD Pipeline

The GitHub Actions workflow acts as the automation layer responsible for triggering and managing the Azure Machine Learning workflow.

The workflow is started manually using GitHub’s workflow_dispatch trigger.

name: deploy-model-training-pipeline

on:
  workflow_dispatch:

This allows users to execute the machine learning workflow on demand from the GitHub Actions interface.

The workflow runs on:

runs-on: ubuntu-latest

and uses Azure CLI commands to communicate with Azure Machine Learning resources.

GitHub Actions Pipeline Components

1. Get Config

The first job retrieves shared configuration values used throughout the workflow.

get-config:
  runs-on: ubuntu-latest
  outputs:
    resource_group: ${{ steps.config.outputs.resource_group }}
    aml_workspace: ${{ steps.config.outputs.aml_workspace }}

Purpose

  • Defines common configuration values.
  • Retrieves the Azure Resource Group name.
  • Retrieves the Azure Machine Learning Workspace name.
  • Exposes these values as outputs for downstream jobs.

This prevents configuration values from being duplicated throughout the workflow.

2. Register Environment

This job registers the Azure Machine Learning environment.

az ml environment create \
  --file ML/environment.yaml \
  --resource-group "${{ needs.get-config.outputs.resource_group }}" \
  --workspace-name "${{ needs.get-config.outputs.aml_workspace }}"

Purpose

The environment defines the runtime configuration used by all machine learning jobs, including:

  • Python version
  • Required packages
  • Library dependencies
  • Runtime settings

Registering the environment ensures that all jobs execute in a consistent and reproducible environment.

3. Register Dataset

This job registers the dataset inside Azure Machine Learning.

az ml data create \
  --file ML/data.yml \
  --resource-group "${{ needs.get-config.outputs.resource_group }}" \
  --workspace-name "${{ needs.get-config.outputs.aml_workspace }}"

Purpose

  • Registers the NYC Taxi dataset.
  • Creates a reusable dataset reference.
  • Makes the dataset available to Azure ML jobs.

After registration, the dataset can be accessed consistently across multiple pipeline executions.

4. Run Pipeline

This job starts the Azure Machine Learning Pipeline.

az ml job create \
  --file ML/pipeline.yaml \
  --resource-group "${{ needs.get-config.outputs.resource_group }}" \
  --workspace-name "${{ needs.get-config.outputs.aml_workspace }}"

Purpose

This is the primary workflow step that initiates the end-to-end machine learning process inside Azure Machine Learning.

Azure Machine Learning Pipeline

The Azure Machine Learning Pipeline is defined in the pipeline.yaml file.

$schema: https://azuremlschemas.azureedge.net/latest/pipelineJob.schema.json
type: pipeline

display_name: NYC_Taxi_ML_Pipeline
description: ML pipeline for NYC taxi analysis

The pipeline runs inside the Azure Machine Learning Workspace and executes multiple machine learning jobs in sequence.

Compute Target

All jobs run on the Azure Machine Learning compute target named capstone.

settings:
  default_compute: azureml:capstone

Purpose

The compute target provides:

  • CPU resources
  • GPU resources (if configured)
  • Managed execution environment
  • Scalable compute for ML workloads

All stages of the pipeline execute using this compute resource.

Pipeline Input

The pipeline uses the latest registered NYC Taxi dataset.

inputs:
  data_path:
    type: uri_folder
    path: azureml:taxi-data@latest

Purpose

The dataset reference points to the most recent version of the registered dataset.

Using versioned datasets improves reproducibility and data governance.

Azure ML Pipeline Execution Stages

1. Preprocess Data

The first stage executes the preprocess.py script.

preprocess_data:
  type: command
  command: >-
    python preprocess.py
    --data-path ${{inputs.data_path}}
    --output-dir ${{outputs.output_dir}}

Purpose

This stage prepares the raw NYC Taxi dataset for model training by:

  • Removing invalid records
  • Handling missing values
  • Cleaning the dataset
  • Removing unnecessary columns
  • Preparing training features

The cleaned data is written to an Azure ML datastore-backed folder.

2. Supervised Learning

After preprocessing completes, the supervised learning stage begins.

supervised_learning:
  type: command
  command: >-
    python supervised_learning.py
    --data-path ${{inputs.data_path}}
    --output-dir ${{outputs.output_dir}}

Purpose

This stage trains a supervised machine learning model using the cleaned dataset.

The model predicts:

  • Taxi fare amounts
  • Trip-related outcomes based on journey characteristics

The input comes directly from the preprocessing stage.

inputs:
  data_path: ${{parent.jobs.preprocess_data.outputs.output_dir}}

This creates a dependency between preprocessing and model training.

3. Unsupervised Learning

The unsupervised learning stage also uses the preprocessed dataset.

unsupervised_learning:
  type: command
  command: >-
    python unsupervised_learning.py
    --data-path ${{inputs.data_path}}
    --output-dir ${{outputs.output_dir}}

Purpose

This stage applies clustering techniques to identify patterns in taxi trip behavior.

Examples include:

  • Short city trips
  • Airport trips
  • Peak-hour rides
  • Long-distance journeys

The stage receives its input from the preprocessing output.

4. Register Models

Once training completes, the generated models are registered.

register_models:
  type: command
  command: >-
    python register_models.py
    --supervised-dir ${{inputs.supervised_dir}}
    --unsupervised-dir ${{inputs.unsupervised_dir}}

Purpose

This stage stores trained models in the Azure Machine Learning Model Registry.

Benefits include:

  • Version tracking
  • Model comparison
  • Reusability
  • Deployment readiness

The registry becomes the centralized repository for trained models.

5. Monitoring

The final stage executes the monitoring script.

monitoring:
  type: command
  command: >-
    python monitoring.py
    --data-path ${{inputs.data_path}}
    --supervised-output-dir ${{inputs.supervised_dir}}
    --unsupervised-output-dir ${{inputs.unsupervised_dir}}
    --output-dir ${{outputs.output_dir}}

Purpose

This stage generates:

  • Monitoring artifacts
  • Performance reports
  • Validation outputs
  • Execution logs

These outputs help evaluate pipeline performance and support future model improvements.

How the Jobs Run

Each stage of the pipeline is implemented as an Azure ML Command Job.

environment: azureml:taxi-ml-env@latest
code: ./

Environment

Each job uses:

azureml:taxi-ml-env@latest

This environment contains:

  • Python runtime
  • Machine learning libraries
  • Required dependencies

Source Code

code: ./

This instructs Azure Machine Learning to use the current project directory as the source code location.

Execution Model

All jobs execute as containerized workloads on Azure ML compute resources.

Benefits include:

  • Consistent runtime environments
  • Dependency isolation
  • Reproducibility
  • Scalability

End-to-End Workflow

The complete workflow executes in the following order:

  1. User manually triggers the GitHub Actions workflow.
  2. GitHub Actions retrieves configuration values.
  3. GitHub Actions authenticates with Azure.
  4. The Azure ML environment is registered.
  5. The NYC Taxi dataset is registered.
  6. GitHub Actions starts the Azure ML Pipeline.
  7. Azure ML preprocesses the data.
  8. Supervised learning models are trained.
  9. Unsupervised learning models are trained.
  10. Models are registered in Azure ML.
  11. Monitoring artifacts and logs are generated.
  12. Outputs are stored in Azure ML datastore locations.

Summary

This project combines GitHub Actions and Azure Machine Learning to create a complete MLOps workflow.

The GitHub Actions pipeline acts as the orchestration layer responsible for starting and managing the workflow, while the Azure ML Pipeline performs the actual machine learning operations.

Together they provide:

  • Automated model training
  • Reproducible experiments
  • Dataset versioning
  • Environment management
  • Model registration
  • Monitoring and tracking

This architecture demonstrates a production-style machine learning workflow where data processing, model training, and model management are fully automated and repeatable.
